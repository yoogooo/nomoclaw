# VERSIONING

## 一、概述

本文档定义项目的版本号规范与构建产物命名规则，目标如下：

- 保持对外版本简洁稳定
- 支持一天内多次构建发布
- 实现构建可追溯
- 便于自动化发布与运维管理

------

## 二、版本号结构

| 项目       | 格式                             | 示例                 | 说明         |
| ---------- | -------------------------------- | -------------------- | ------------ |
| 完整版本号 | `major.minor.patch+yyMMdd.SSSSS` | `1.0.0+260415.42305` | 用于内部追踪 |
| 对外版本号 | `major.minor.patch`              | `1.0.0`              | 用户可见     |
| 构建号     | `yyMMdd.SSSSS`                   | `260415.42305`       | 内部使用     |

------

## 三、对外版本号（SemVer）

### 格式

```
major.minor.patch
```

### 规则

| 字段  | 含义   | 触发条件          |
| ----- | ------ | ----------------- |
| major | 主版本 | 不兼容变更        |
| minor | 次版本 | 向下兼容的新功能  |
| patch | 修订号 | bug 修复 / 小优化 |

### 示例

| 类型     | 示例    |
| -------- | ------- |
| 初始版本 | `1.0.0` |
| 新功能   | `1.1.0` |
| 修复     | `1.1.1` |
| 重大升级 | `2.0.0` |

### MSI 约束（Windows）

| 字段  | 限制    |
| ----- | ------- |
| major | ≤ 255   |
| minor | ≤ 255   |
| patch | ≤ 65535 |

------

## 四、构建号

### 格式

```
yyMMdd.SSSSS
```

### 字段说明

| 字段  | 示例  | 说明       |
| ----- | ----- | ---------- |
| yy    | 26    | 年份后两位 |
| MM    | 04    | 月份       |
| dd    | 15    | 日期       |
| SSSSS | 42305 | 当天偏移秒 |

------

## 五、偏移秒计算规则

### 公式

```
SSSSS = hour * 3600 + minute * 60 + second
```

### 示例

| 时间     | 计算过程            | 结果  |
| -------- | ------------------- | ----- |
| 00:00:00 | 0                   | 0     |
| 11:45:05 | 11×3600 + 45×60 + 5 | 42305 |
| 23:59:59 | 最大值              | 86399 |

### 取值范围

```
0 ~ 86399
```

------

## 六、完整版本号

### 格式

```
major.minor.patch+yyMMdd.SSSSS
```

### 示例

| 构建时间            | 完整版本号           |
| ------------------- | -------------------- |
| 2026-04-15 00:00:00 | `1.0.0+260415.0`     |
| 2026-04-15 11:45:05 | `1.0.0+260415.42305` |
| 2026-04-15 23:59:59 | `1.0.0+260415.86399` |

------

## 七、排序规则

按以下优先级排序：

| 顺序 | 字段   |
| ---- | ------ |
| 1    | major  |
| 2    | minor  |
| 3    | patch  |
| 4    | yyMMdd |
| 5    | SSSSS  |

说明：

- 先比较语义版本
- 再比较构建时间
- 时间越晚 → 版本越新

## 九、文件命名规则

### 格式

```
<ProductName>-<version>-<platform>.<ext>
```

### 示例

```
NomoClaw-1.0.0-windows-x64.msi
```

------

## 十、字段说明

### 1. ProductName

| 规则     | 说明                |
| -------- | ------------------- |
| 命名风格 | PascalCase          |
| 禁止     | 空格 / 中文 / emoji |

示例：

- `NomoClaw`
- `MyApp`

------

### 2. version

| 规则 | 说明                  |
| ---- | --------------------- |
| 使用 | `major.minor.patch`   |
| 禁止 | build 号 / + / 预发布 |

------

### 3. platform

| 平台        | 示例            |
| ----------- | --------------- |
| Windows     | `windows-x64`   |
| Windows ARM | `windows-arm64` |
| macOS       | `macos-arm64`   |
| Linux       | `linux-x64`     |

------

### 4. ext

| 类型   | 示例      |
| ------ | --------- |
| 安装包 | msi / exe |
| macOS  | dmg       |
| Linux  | AppImage  |

## 十三、设计原则

- 对外版本简洁稳定
- 内部构建可精确追踪
- 支持一天内多次发布
- 不依赖人工递增
- 文件名稳定且可自动化
- 构建信息不污染对外版本

------

## 十四、Bash 生成示例

```bash
APP_VERSION="1.0.0"

BUILD_DATE="$(date +%y%m%d)"
HOUR="$(date +%H)"
MINUTE="$(date +%M)"
SECOND="$(date +%S)"

SECONDS_OF_DAY=$((10#$HOUR * 3600 + 10#$MINUTE * 60 + 10#$SECOND))

BUILD_NO="${BUILD_DATE}.${SECONDS_OF_DAY}"
FULL_VERSION="${APP_VERSION}+${BUILD_NO}"

echo "APP_VERSION=${APP_VERSION}"
echo "BUILD_NO=${BUILD_NO}"
echo "FULL_VERSION=${FULL_VERSION}"
```
